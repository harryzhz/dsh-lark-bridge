# UI 设计、交互规范与验收标准

修改 `packages/dsh-lark-ui` 下的任何组件、弹窗、表单、图表或样式前必须阅读并严格遵守本文档；**UI 交付验收不止于「无 bug、功能正常」，还必须同时满足「页面简洁美观」与「交互合理自然」**。

## 0. 核心审美基线（简洁、美观、克制）

- **全站视觉标杆**：以**「驾驶舱」**（低噪精密遥测仪器感、统一面板语言、严格中轴对齐）与三栏**「记忆库」**（Bear / Apple Notes 式无框精读纸面）为设计标杆；**坚决拒绝「卡片套卡片」的后台 CRUD 表单堆砌、高密度多行微卡片与彩色徽章污染**。
- **信息减法优先（能省则省）**：每个区域只保留当前决策真正需要的高信噪比信息——
  - 列表项保持轻盈可扫描，不塞正文摘要、重复分类文字、零值噪声（如「未召回」）或内部 ID 哈希；
  - 详情页把元信息收口到单行眉题，跳转入口收口为单行横排纯链接（清晰链接标题 + tooltip 承载完整路径/标题，不加冗长前置文案），长尾标签默认折叠（`+N`）；
  - 不在标准列表页顶部额外塞提示条（hint bar）或冗长操作指南，保持页面留白与呼吸感。
- **克制配色与协调字号层级**：100% 复用 `--dsw-*` 语义色令牌与 `color-mix`（零硬编码色值，亮/暗双模式视觉等质），跨页面与同页子面板共享统一视觉语言；字号比例严格协调（主标题 > 区块标题 > 控件与正文 > 辅助元信息），禁止局部切换器、标签或标题字号过大喧宾夺主。
- **可视化清晰克制**：图表与读数条必须保证一眼可读，**拒绝文字密集挤在一起的拥挤排版**；优先用「单行 HUD 读数条 + 留白充足的语义色图形/比例条」承载核心指标，把全量明细放进悬停联动（hover HUD / tooltip），不把所有统计字段硬塞在静态表面。
- **文案直白、口径明确、维度正交**：去掉内部术语与冗余修饰（如「四种分类」→「分类」、「作用域层级」→「层级」）；所有指标与图表必须清晰标明**统计主体、口径与人类可读单位**（如明确区分回复耗时 / 接口耗时 / SQLite 慢查询 `≥100ms`，耗时用 `8m 41s` 而非裸 `520.9s`），不同概念维度（如具体模型名 vs Agent 维度）正交呈现，严禁把内部兜底占位符（如 `(default)`）直接与实体名混排暴露给用户。

## 1. 设计令牌、主题与主容器尺寸一致

- **设计令牌与主题**：全面复用 `@deepseek-ai/dsh-client-ui-primitives` 原生控件与 `--dsw-*` 主题令牌，自动适配亮/暗双模式；**严禁硬编码颜色值**，严禁向终端用户暴露裸 JSON 输入框。
- **所有主页面 Tab 统一自适应容器尺寸（硬性规范）**：
  - 飞书桥接工作台主页的所有标签页（含现有「驾驶舱」「智能体」「群聊」「自动化」「记忆库」「会话」以及**后续新增的所有 Tab 页**）必须共享唯一自适应主容器 `.fb-container`（`width: 100%` + 响应式左右边距 `clamp(24px, 3vw, 48px)`，**禁止锁死在窄固定宽度如 `960px`**），在大屏幕上自动展宽以展示更多信息，在小屏幕下优雅收缩。
  - **严禁单 Tab 特殊覆写容器宽度或边距**：禁止对特定 Tab 覆写 `max-width` 或修改顶栏/Tab 栏外边距（如 `data-workspace`、`data-dashboard` 等局部特例），确保在任意屏幕尺寸下切换任意 Tab 时，顶栏标题、右侧操作区、Tab 导航条与主体空间尺寸保持零位移、完全一致。
  - **多栏工作区与图表的大屏自适应**：
    - 存在多栏并列结构的 Tab（如三栏「记忆库」）须收纳在统一 `.fb-container` 内的圆角细边框工作区卡片（`.fb-mem-frame`）中，列宽使用容器相对比例 `clamp(...cqi...)` 随大屏自然展宽、小屏经 `@container` 降级，高度随视口自适应（`max(540px, calc(100vh - 180px - ...))`，不设窄高度天花板）；正文精读纸面（`.fb-mem-paper`）保留舒适行宽上限（`780px`）。
    - 驾驶舱全宽 SVG 时序图须经 `ResizeObserver` 按容器实测像素宽度动态计算 `viewBox`，确保大屏展宽时保持 `1:1` 像素清晰度、字号不放大、图高不畸变。

## 2. 配置项控件右侧统一对齐规范

- **单一主控件右对齐**：`<SettingRow>` 右侧控件区仅放置**单一主控件**并与容器右边界严格齐平，**禁止在下拉选择框、输入框等配置控件后再追加独立按钮或第二个输入控件**。
- **下拉关联管理入口**：与下拉选项强关联的管理/新建入口统一收纳进下拉菜单底部固定区（`SelectMenu` `footer` / DSH 原生 `Menu.footer`），不挤占配置行右侧空间。
- **输入框行内附属动作**：如目录浏览图标、环境变量行移除 `×` 等附属动作，须**内嵌于输入容器右端**（如 `.fb-dir-control`、`.fb-env-val-box`），保证外轮廓与上下配置控件严格右对齐。
- **条件触发的补充输入**：由某选项触发的补充输入项（如自定义时长、自定义签名）统一展开为下方 `<NestedSettings>` 二级配置行，禁止横排拼接在原选择框旁。
- **命令/批量导入区**：需要额外触发按钮的命令或批量导入区采用上下堆叠布局（输入区在上、说明与右对齐按钮在下），禁止在输入框尾部横接按钮。

## 3. 弹窗层级与二级管理视图规范

- **禁止同级双弹框叠层**：严禁在主配置弹窗（如 `ConfigDialog`、`CreateBotDialog`）之上再弹出同尺寸二级 `<Modal>`，避免双层遮罩叠加导致页面背景色变暗及整窗生硬覆盖。
- **原位下钻子视图**：从配置弹窗进入二级管理界面或目录浏览（如外部 Agent 启动配置管理 `RuntimeProfilePanel`、本地工作目录选择 `DirectoryPickerPanel`）须在同一 `<Modal>` 内原位切换为子视图：
  - 顶部提供面包屑返回按钮（`‹ 上级视图 / 子视图标题`）；
  - 支持 `Escape` 逐级返回（优先关闭已展开的下拉菜单、新建输入框或清空非空筛选词）；
  - 全程保留父级未保存草稿。
- **轻量辅助小窗遮罩抑制**：仅确认明显窄于父弹窗的只读/授权小窗（如扫码授权 `LarkAuthDialog`、只读工具 Schema 预览）允许在宽父弹窗上叠层打开，且必须标记 `.fb-nested-modal` 抑制二次遮罩与二次模糊，不得加深页面背景。

## 4. 开关展开层级、缩进与子分组规范（`<NestedSettings>` / `.fb-nested`）

- **何时不缩进（平铺展开）**：
  - 当整个配置 Tab（如机器人/群「角色设定」、群「主动监听」）、独立弹窗（如定时任务「启用飞书通知」），或某个 `<GroupTitle>` 分组内**仅存在单一总开关或模式切换**（如「主运行时」「智能分流」「消息卡片」「私聊」「代答」「Dreaming 与长期记忆」）时，该行仅作为「是否开启 / 模式来源」开关，**下方展开的配置项禁止使用 `<NestedSettings>` 整体缩进**，直接按一级配置行平铺，避免整页或整组被无意义地向右推挤。
- **何时使用 `<NestedSettings>` 缩进**：
  - **仅当同一分组内存在多个同级配置开关或同级配置项**，且其中某一项展开附属子配置或条件补充输入、需要与同组其他配置项区分归属边界时，才使用 `<NestedSettings>` 缩进，例如：
    - 同一分组内并列多个功能开关（如「主动工作」分组下的「主动创建提醒事项」与「主动代码优化与提审」，以及「提醒创建方式」同级的「夜间免打扰」）；
    - 同一分组内某一项的二级附属开关或条件补充输入（如「消息卡片」平铺展开后的「附带会话链接 → 允许群成员只读查看」、「卡片底部签名 → 签名内容」，「触发与会话」中的「空闲自动归档 → 归档时长」，「编辑记忆」中的「作用域 → 目标群聊 ID / 目标工作目录」）。
- **缩进容器样式**：
  - `<NestedSettings>` 展开的二级配置**不加背景底色与圆角框**，右侧控件与一级配置严格右对齐（`padding-right: 0`）。
  - 左侧采用与配置项间横线一致的细引导竖线（`0.5px solid var(--dsw-alias-border-l2)`），高度对齐子配置首尾内容。
  - 展开二级配置时自动收起父项底部横线（`.fb-row:has(+ .fb-nested)`）。
- **多配置项分组拆分**：当同一开关或独立覆盖平铺展开的配置项较多（通常超过 5 项，或跨越不同语义维度，如「主动监听」中的「监听对象 / 消息过滤 / 回复策略」、「智能分流」中的基础项与「分流 Prompt」）时，首段核心配置紧跟总开关平铺，后续按语义使用 `<GroupTitle>` 划分为清晰分组，避免大量表单项平铺堆叠或出现冗余的「基本配置」二次标题；同组内按「主配置 → 附属控制」顺序组织。

## 5. 文案克制与分组说明

- **配置项说明克制**：表意自明的配置项（如显示名称、App ID、工作目录、模型、允许私聊、提醒创建方式、分支前缀等）**不加冗余描述**；非自明项仅写单句准确说明，避免长段落堆砌。
- **下拉选项克制**：表意自明的下拉选项保持紧凑单行菜单，**不给所有下拉项强加副标题**；仅在选项间存在非直观语义差异（如代答身份说明、应用创建通道）时提供单行区分说明。
- **正式功能与实验性功能的说明样式边界**：
  - **正式功能**：**不使用灰色圆角说明卡片**（`.fb-banner`），与其他常规配置保持一致，在开关或策略首行的 `<SettingRow desc>` 用单句简要说明即可。
  - **实验性功能**：允许在对应 `<GroupTitle>` 分组标题正下方使用灰色圆角说明卡片（`.fb-banner` / `.fb-dream-card`），采用无小标题、无列表圆点（bullet）的单段机制说明，按需附带运行状态与手动触发入口；与上下内容之间不加横线分隔。
  - 分组标题前的末尾配置项统一隐藏底部分隔横线（`.fb-row:has(+ .fb-group-title)`）。

## 6. 切换器、列表筛选工具栏与可编辑标签流

- **主视图切换器**：使用分段控制器（`<CountSegmentedSwitch>` / `SegmentedControl`），高频或基础能力置于左侧（如「自动化」页 `定时任务` 在左、`提醒事项` 在右；「会话」页 `会话` 在左、`运行日志` 在右）。
- **平级分类/状态筛选一律横排**：列表内的平级分类、状态或事件类型筛选（通常 `≤ 6` 项高频枚举，如会话类型、运行日志事件类型、提醒事项状态、记忆历史状态）统一对齐 DSH `TaskManagerPage` 轻标签样式（`<FilterTabs>` / `.fb-filter-tab`：`height: 28px; border: 0; border-radius: 14px`，未选中透明底 + `--dsw-alias-label-tertiary` 文字，选中态 `--dsw-alias-interactive-bg-hover` 底 + `--dsw-alias-label-primary` 文字），不使用带深色边框的 `Pill` 胶囊，也**禁止同类平级枚举在一处用横排标签、另一处退回下拉 `<SelectMenu>`**。「全部」筛选项在横向标签内统一写作 `全部`（不赘述 `全部事件` 等冗余后缀）。
- **数量数字样式**：切换器与筛选标签内的数量**不加括号 `()`**，统一紧跟文案右侧显示浅灰色等宽数字（`.fb-tab-count`：`color: var(--dsw-alias-label-tertiary); font-variant-numeric: tabular-nums`）。
- **列表页双层工具栏标准结构**：
  - **第一层（视图与分类栏 `.fb-view-bar`）**：存在子视图切换的列表页（如「自动化」「会话」）顶部固定为单行两端对齐工具栏——左侧放 `<CountSegmentedSwitch>`，右侧 `.fb-view-bar-right` 放当前子视图的 `<FilterTabs>` 及页内轻量辅助操作（`Button variant="ghost"`）。
  - **第二层（检索与智能体筛选栏 `<ListFilterBar>` / `.fb-toolbar`）**：标准单栏列表主视图（群聊、自动化、会话与运行日志）在列表卡片正上方统一使用 `<ListFilterBar>`——左侧全宽搜索框（`Input.fb-search`，`36px` 高），右侧在存在多个智能体（`bots.length > 1`）时固定放置智能体过滤下拉框（`<SelectMenu>`，`36px` 高，首项 `全部智能体`）。**禁止按列表条目数（如 `> 4`）条件隐藏过滤栏**，避免切换视图或增删条目时工具栏跳动。
  - **三栏精读工作区（如「记忆库」）**：在统一自适应 `.fb-container` 内以圆角细边框工作区卡片（`.fb-mem-frame`）承载三栏结构（左栏导航树含与其他页面一致的无边框浅底胶囊 `<SelectMenu fullWidth>` 智能体切换、`全部有效 / 核心置顶 / 历史演进`、`分类`、左对齐的 `层级` 与默认折叠长尾的 `常用标签`；中栏极简两行列表项仅展示标题 + 分类色点/作用域/置顶与日期，**不展示正文摘要与零值噪声**；右栏纯白/暗色无框精读纸面，顶部单行眉题合并分类与核验/召回元信息、正文下方标签轻量化、底部所有跳转链接收口为**单行横排纯链接**且不附带冗长前缀文案，详情放在 tooltip 悬停提示），列宽按 `cqi` 随大屏自适应展开、高度随视口铺展，全程复用 `--dsw-*` 语义色令牌且禁止硬编码颜色。
  - **驾驶舱多维观测台（「驾驶舱」：概览 / 洞察 / 监控）**：与常规列表页严格共享同一自适应容器宽度（`.fb-container`，切换顶栏 Tab 零跳动，大屏自动展宽显示更多明细），采用顶部单行控制条（左侧 `<CountSegmentedSwitch>` 切换「概览 / 洞察 / 监控」+ LIVE 指示，右侧在洞察/监控面板展示默认 `24h` 的周期分段 `24h / 7d / 30d / 90d` + 智能体/渠道下拉、非默认筛选态的「重置筛选」与刷新）；**三个子面板共享同一套精密遥测卡片体系（`.fb-obs-kpi`、`.fb-obs-panel` 卡内标题、`.fb-obs-hud` 读数条、按容器宽度 `1:1` 重算 `viewBox` 的 `.fb-obs-svg` 语义色图表与 `.fb-obs-grid-2` 50%/50% 中轴对齐栅格）**，禁止概览退回旧式黑白柱图或外部浮动标题，禁止上下两排错位比例混搭；所有 SVG 图表、热力矩阵、分段条、增量徽章均通过 `--dsw-*` 语义色与 `color-mix` 渲染，零硬编码色值。
    - **Token 消耗维度正交**：`Token 结构与消耗` 面板通过卡内 `<FilterTabs>` 提供对称的 `按模型` / `按 Agent` 切换视角——`按模型` 严格按步级真实上报模型名聚合（禁止伪造 `<agent> (default)` 混入 Agent 名），`按 Agent` 按执行引擎（如 Antigravity / Codex / DSH 原生模式 / 智能分流）汇总并列出关联模型。
    - **维度排行局部展开**：`维度消耗排行` 卡片内部仅执行局部切换（`群聊 / 私聊` ↔ `智能体`）与原位行内明细展开（Token 构成与关联模型），严禁点击排行行反向篡改页面顶层全局筛选或折叠同级排行列表。
- **多维度筛选联动与空态约定**：
  - **智能体作用域保持**：智能体筛选属于页面级作用域维度，同一页面内切换子视图（定时任务 ↔ 提醒事项、会话 ↔ 运行日志、有效记忆 ↔ 历史演进）时保持已选智能体不变、仅清空关键词搜索；若已选智能体被移除或仅剩单个智能体，须经 `resolveEffectiveBotId` 自动回退至 `全部智能体`。
  - **作用域联动计数**：选定具体智能体后，顶层 `<CountSegmentedSwitch>`、`<FilterTabs>` 与三栏左侧导航目录的数量角标同步按该智能体作用域重算；关键词搜索仅过滤当前列表行，不扰动左侧分类与层级计数。
  - **空态分层**：全局无数据时展示引导空态文案；由智能体筛选、分类筛选或关键词搜索导致的空列表统一展示 `没有匹配的…`（如 `没有匹配的群聊`、`没有匹配的定时任务`、`没有匹配的会话`、`没有匹配的日志`、`没有匹配的记忆`）。
- **单层可编辑标签流**：支持增删改的标签集合（`<EditableScopeList>`）使用单一标签列表（点击文字原位编辑、`×` 移除、行内 `+ 添加`、仅偏离默认值时显示「恢复默认」），禁止同时渲染预设胶囊栏与已选标签栏造成重复。

## 7. 交互合理性、作用域边界与状态韧性

- **交互作用域与控件层级严格一致（局部不扰全局）**：
  - **全局控制归位顶层**：影响整页或多个面板的筛选维度（如时间周期、智能体、群聊等）统一置于页面顶层/底层控制条，并清晰回显已选状态与一键重置入口。
  - **局部交互只作用于当前组件**：单个图表、排行列表或卡片内部的交互（如悬停联动 HUD、点击切换当前图表视角、展开当前条目明细）**只能影响当前图表或局部面板**；**严禁点击单张图表内部行导致整页布局重排、其他无关面板跳变或隐式改写全局筛选条件**。
- **配置控制面单一真相，同类交互全站一致**：
  - 同一行为的控制逻辑与入口收口在唯一位置，禁止跨面板重复配置或语义冲突；将模块迁至新位置后立即清理旧入口。
  - 同类页面（如群聊 / 自动化 / 会话 / 运行日志）在筛选形态（`<ListFilterBar>`、横排 `<FilterTabs>`、无边框浅底胶囊 `<SelectMenu>`）、排序方式、数量角标与作用域保持策略上保持全站一致，禁止随条目数条件显隐工具栏造成界面跳动。
  - 导航与信息架构顺序符合用户高频使用心智（如主 Tab 排序为 `驾驶舱 / 智能体 / 群聊 / 自动化 / 记忆库 / 会话`，层级树中 `全局记忆` 固定置顶）。
- **过程无感、性能流畅与失败态原位可控**：
  - 切换 Tab、轮询刷新与插件热更新等操作须尽量无感——利用缓存与状态保持避免白屏闪跳、UI 突然消失或强制跳离当前 Tab；高频页面不得因 N+1 查询或重复全表扫描造成明显加载卡顿。
  - 阻塞态或失败态（如热更新排空等待、超时或安装失败）必须在 UI 原位给出清晰状态与可控兜底动作（如「跳过等待，强制更新」「强制重试」），不迫使用户退回 CLI 处理。

## 8. 交付前 UI 验收标准（四维硬性门禁）

凡涉及前端页面、弹窗、图表、样式或交互改动的 PR，在合入 `main` 前必须在真实浏览器中完成实测，并**针对改动页面与关联主视图截取清晰画面（覆盖亮/暗双模式，以及常规视口与宽屏视口，必要时核验窄屏降级）逐项评审**。以下四个维度**全部达标**方可放行；任一项存在明显瑕疵（即使零报错、功能全通）均视为验收不通过，须先打磨优化再交付：

| 验收维度 | 核心标准 | 必查门禁项（一票否决） |
| --- | --- | --- |
| **1. 功能与零异常（底线）** | 逻辑正确、运行稳定 | 无未捕获 `pageerror`、`console.error` 与接口 4xx/5xx；新增/改动配置的编辑、保存、重新打开回显、恢复默认与条件联动闭环正常；空态、加载态、错误态与跨页跳转链路正常；页面加载与切 Tab 流畅无卡顿闪烁 |
| **2. 美感与简洁度（核心）** | 干净、克制、有美感 | 第一眼观感清爽、留白与呼吸感充足；无「卡片套卡片」、高密度多行微卡片、多余提示条、重复字段、零值噪声或裸 Markdown/内部 ID 污染；图表文字不拥挤，明细通过悬停 HUD/tooltip 渐进呈现；字号比例协调不突兀；亮/暗双模式与跨面板配色、控件风格完全统一（零硬编码颜色） |
| **3. 布局、对齐与自适应（精度）** | 齐整、无截断、大屏舒展 | 主页所有 Tab 共享 `.fb-container`（切换 `0px` 位移、大屏自然展宽、小屏无横向溢出）；图表栅格严格中轴对齐，全宽 SVG 按容器宽 `1:1` 清晰渲染不失真；配置行单一控件严格右对齐、单开关平铺不缩进；所有文字、标签与下拉选项完整显示或标准省略配 tooltip，无裁切重叠 |
| **4. 交互合理性与语义清晰（体验）** | 符合直觉、零困惑 | 局部图表交互仅影响当前组件，不触发整页跳变，全局筛选统一归位顶层控制条；同类功能交互形态全站统一，不随数据量显隐工具栏；二级视图原位下钻无同级双弹框叠层且保留草稿；过程无感、阻塞/失败态有原位可控兜底入口；指标主体、统计口径、人类可读单位与实体维度（如模型 vs Agent）正交直观、文案直白无术语堆砌 |
